# 逻辑推理 · Agent 工作日志（模块实例）

> 由通用模板 `经验/4-Agent工作日志模板.md` 实例化而来。接手本模块的 AI 先读本文件再操作。
> 参考同仓实例：`图推/agent日志.md`。

## 一、工作模式

- 用户负责写入：学习时随手把笔记、截图贴进文档（习惯贴在文末，裸贴）
- AI 负责整理：核对内容 → 判断是否与已有章节重复 → 归类 / 开新节 → 提炼要点 → 标注来源 → 全量校验图片链接
- 大改动前先给"目标 + 方案"，用户确认后执行

## 一之一、交互约定（2026-10-18 用户指定）

- 用户丢一道题 → **默认只讲解，不写文件**；用户说"存/记下来/归档"才写入 `逻辑推理题目练习.md`
- 讲解遇到与笔记已有结论冲突的，当场指出，并问是否更正笔记
- 其余"大改动前先给目标+方案再执行"的规则不变

## 二、维护范围（硬性规则）

- 只整理 `逻辑推理/` 这一个目录，不碰仓库其他部分
- 只维护以下文件：
  - `逻辑推理提纲学习.md` —— 课程考点主文档
  - `逻辑推理题目练习.md` —— 具体题目记录
- 固定区块：
  - `逻辑推理提纲学习.md` 顶部"总览 · 知识点全景"图（花生老师《3小时速通·27年最新判断推理》截图）—— 严禁移动 / 替换 / 删除，作为本模块锚点
  - 其余正文可自由增删调整

## 三、文档规范

- 图片统一放 `逻辑推理/images/`，md 内用相对路径 `images/xxx.png` 引用（不用 `../images/`）
- 图片命名：见「三之二」—— `编号号-考点-来源或关键词.png`（旧的时间戳命名 `image-YYYYMMDDHHMMSS.png` 已废弃，不要再新建）
- 每个章节标注来源（老师名 / 课程名 / 真题年份 + 题号）
- 去重规则：与已有章节重复的内容合并去重，图片文件留磁盘不删；未被 md 引用的备用图移到 `逻辑推理/assets/`
- 整理完成后必须全量校验图片引用，确保零死链
- 不要在图片 URL 后加 fragment；不用 `style=` 控宽（GitHub 会剥离）

## 三之二、图片编号与索引（2026-10-18 用户指定）

- **每张图有编号**，两位补零（`00` 锚点图，`01` 起为题目图），文件名即 `编号号-考点-来源或关键词.png`
- **编号只增不复用**：删图留空号，空号不再分配
- **索引在隐藏目录**：`.workbuddy-ai/notes/图片索引.md` —— 每张图一行，写清「内容 / 手写批注 / 来源 / 用在 / 状态」，是原图的**文本替身**
- **整理时先读索引，不读图**：索引里有的图不再打开；只有索引缺失或需核对原图时才读，且读完必须回填索引
- **排布文档靠索引**：图多了以后，用索引的文字描述分组 → 生成章节骨架 → 挂编号 → 做缺口检测（索引有文档无 = 待归档；文档有索引无 = 断链）
- 状态文件 `.workbuddy-ai/notes/state.json`：记录游标（bytes + tail_hash）、`next_image_no`、待补清单
- 流程图与规则见 skill（两级）：
  - 通用流程：用户级 `~/.workbuddy-ai/skills/md-note-organizer/`（含模板 + 初始化 + 校验脚本）
  - 本项目约定：项目级 `.workbuddy-ai/skills/luoji-notes/SKILL.md`
